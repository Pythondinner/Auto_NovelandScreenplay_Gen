# 自动剧本生成机

一个通过自然语言对话收集创作需求、自动生成小说/剧本正文的写作辅助工具。跟 AI 聊几句你想写的故事，它会帮你把零散的想法整理成结构化的创作设定，并生成一版可用的正文草稿——长篇会自动分段生成、保持前后衔接，多幕故事可以连续续写、维持人物和情节的一致性。

- **一句话定位**：不是"填表生成器"，是能聊、能追问、能记住上下文的创作搭档——你负责创意和取舍，它负责把对话变成可执行的写作大纲，再把大纲落成正文。
- **技术栈**：Python + Flask（Web 后端）+ 原生 HTML/JS（前端），调用 DeepSeek API 做需求理解和正文生成，无需其他重型依赖。

## 核心特性

### 对话式需求收集，不是表单
跟你聊你想写的故事，从只言片语里推断类型、基调、人物、场景，能推断的不追问，只有在信息实在不够、编不出一个像样的故事雏形时才会开口问。收集到的每一项都能在对话里随时用自然语言修改（"把主角的职业改成侦探"），不需要找到某个设置项去改。

### 以"张力"而非"人设"为主线
故事的骨架是一个 want（想要什么）与一个 obstacle（被什么阻挡）之间的对抗，人物只是这股张力的载体——这让生成的内容天然带有冲突和推进感，而不是一堆角色设定的堆砌。支持单主角，也支持多个角色共同承担同一个 want/obstacle 阵营（群像式故事）。

### 双模式输出
同一份创作设定可以分别生成**小说体**（第三人称限知视角散文叙述）或**简化版剧本格式**（场景标题 + 动作描述 + 标准对白格式），互不干扰，可以对照着看同一个故事的两种呈现方式。

### 长篇自动分段生成
篇幅较大的故事会自动拆成多段依次生成，段与段之间会参考"上一段正文"（保持文风一致）和"滚动事实清单"（保持人物状态、已发生事件不冲突），全程对使用者透明——不需要手动分章，生成完是一份完整正文。

### 多幕系列与情节续写
可以基于已完成的故事续写下一幕，自动继承上一幕确立的角色、场景等既有设定，新一幕的核心冲突需要重新确立，不会简单重复。系列内的多幕之间会维护一份滚动事实清单，保证人物状态、关键事件在长链条续写中不会前后矛盾；系列可以随时导出成一份完整合集文档。

### 冲突检测与创作边界
设定之间出现语义冲突（比如同时要求"激烈枪战"又要求"零暴力画面"）会被主动标记出来，交给你决定怎么取舍，而不是自动帮你选一个。对话输入中如果出现疑似试图操纵系统行为的内容，会被识别并标记，但仍然照常处理其中真实的创作诉求。

### 版本管理
同一幕可以反复生成多个版本，互不覆盖，可以随时对照查看、删除某个不满意的版本。

## 系统架构

```
用户对话
   │
   ▼
┌─────────────┐   持久化快照 + 对话记录   ┌─────────────┐
│  交互层       │ ────────────────────────▶ │  存储层       │
│ (对话状态机)  │ ◀──────────────────────── │ (项目/系列/   │
│              │      读取历史设定           │  草稿存档)    │
└──────┬───────┘                           └──────┬──────┘
       │ 设定收尾后                                │ 读取设定 +
       ▼                                          │ 历史正文/事实清单
┌─────────────┐                                   │
│  写手层       │ ◀─────────────────────────────────┘
│ (正文生成，    │
│  长篇自动分段) │
└─────────────┘
```

- **交互层**：一个四态状态机（初始 → 候选方向 → 收集中 → 已收尾），每轮对话用一次模型调用完成理解 + 更新 + 回复，不需要额外的意图分类步骤。
- **存储层**：只负责读写，不做任何判断。项目按文件夹存储，独立项目和系列（多幕续写）用不同的目录结构区分，对外始终用统一的项目名访问。
- **写手层**：把交互层收尾的结构化设定转成正文，长篇自动分段、维护跨段/跨幕一致性，不做修改建议或质量打分。

## 项目结构

```
自动剧本生成机/
├── src/
│   ├── deepseek_client.py   共享的模型调用封装
│   ├── brain.py             交互层：状态机 + 需求理解
│   ├── ledger.py            存储层：项目/系列/草稿的读写
│   ├── writer.py            写手层：正文生成（含长篇分段）
│   ├── chat.py              终端交互入口
│   └── server.py            Web 后端（Flask）
├── web/
│   └── index.html           网页前端（原生 HTML/JS，无构建步骤）
├── requirements.txt
└── .env.example
```

## 快速开始

```bash
pip install -r requirements.txt
cp .env.example .env   # 填入你的 DEEPSEEK_API_KEY
```

**终端版**（最直接的体验方式）：

```bash
python src/chat.py
```

会列出已有项目供选择，或直接开始一个新项目，跟着提示聊你想写的故事即可。

**网页版**：

```bash
python src/server.py
```

启动后访问 `http://127.0.0.1:5057`，左侧对话、右侧实时展示当前收集到的结构化设定，点击任意设定卡片可以直接聚焦输入框针对性修改。

## 使用说明

> 想了解界面上每个字段（主线、假设、子情节、冲突提示……）具体是什么意思、怎么用，看 [USAGE.md](USAGE.md)。

1. 新建或选择一个项目，开始描述你想写的故事——类型、大致情节、想要什么样的人物都可以，说多说少都行。
2. 系统会主动推断能推断的部分，只在必要时追问；随时可以补充、修改已收集的内容。
3. 觉得设定差不多了，说"收尾"（或类似表达）确认，进入生成阶段。
4. 选择生成小说还是剧本格式，等待正文生成完成——篇幅较长时会自动分段，过程中会显示进度。
5. 如果想写系列/多幕故事，可以基于任意一个已收尾的项目创建续集，自动继承已确立的人物/场景设定，只需要重新聊这一幕的核心冲突。全部幕次生成完后可以导出成一份完整合集。

## 已知限制

- 目前只做一次性正文生成，不含自动质量复核/迭代改写环节，生成结果的最终把关仍需要人工通读。
- 同一幕的小说版和剧本版是各自独立生成的，两个模式在具体情节细节上可能存在细微出入。
- 暂无自动化测试套件，暂不支持一键部署到公网（默认只监听本地）。
