# 使用说明书

这份文档解释每个功能是做什么的、为什么这么设计，以及实际使用时该怎么操作。README 里的"快速开始"教你怎么跑起来，这份文档教你怎么用明白。

## 整体流程

```
跟系统聊你想写的故事
        │
        ▼
系统把对话整理成结构化设定（类型、人物、主线、场次大纲…）
        │
        ▼
你确认"收尾" ──▶ 选择生成小说或剧本正文
        │
        ▼
（可选）基于这个故事续写下一幕，形成系列
```

一次典型的使用大概是：聊几句想法 → 看它猜得对不对，边聊边改 → 觉得差不多了说"收尾" → 生成正文 → 不满意就重新生成，或者接着聊改设定再生成。全程不需要填任何表单。

## 界面上的每个部分是什么意思

### 主线（Throughline）
故事的核心冲突，由 **want**（角色想要什么）和 **obstacle**（被什么阻挡）两部分组成，外加一条 **stakes**（如果失败会怎样，用来体现这件事的重要性）。这是整个故事的骨架——所有人物、场次都是为了服务这条主线存在的。一个故事只有一条主线，但可以有很多人物一起承担 want 或 obstacle 的角色（比如一群人共同对抗同一个敌人）。

### 候选方向（Candidates）
只有在你的描述比较开放、能读出好几个不重叠的故事方向时才会出现（比如你只说了"写一个复仇故事"，没说清楚具体是谁复仇、复什么仇）。系统会给出 2-3 个具体的 want/obstacle 组合供你挑，选一个之后就会消失，正式进入设定收集阶段。如果都不满意，直接说想要的方向，系统会重新给候选或者直接按你说的来。

### 角色
每个角色除了姓名/身份，还带三个不直观的字段：
- **embodies**（`want` / `obstacle` / 空）：这个角色是站在"想要"那一边还是"阻挡"那一边，空代表看不出明确站队（比如一个纯服务性的路人）
- **type**（`human` / `non_human` / `internal`）：是不是一个真实存在的人物——`non_human` 用于环境/怪物/抽象力量这类不需要写台词的"角色"，`internal` 用于角色自己的内心挣扎这种没有实体的对抗
- **relation_to_throughline**：这个角色跟主线的关系是直接相关（`aligned`）、支线（`支线`），还是暂时看不清（`unclear`）

### 子情节（Sub-intents）
故事的场次大纲，一条对应一场戏，按顺序写。每条包含这场戏具体讲什么、由谁负责（`assigned_character`）、这场戏里角色遇到的具体阻力是什么（`local_obstacle`）。生成正文时会严格按这个顺序、逐条落实，不会打乱或者遗漏。

### 假设（Assumptions）
系统自己推断、但你没有明确说过的设定，比如你只说了"悬疑"，它可能会猜"基调=紧张压抑"。跟你明确说过的内容分开展示，方便你一眼看出哪些是"我说的"、哪些是"它猜的"——觉得猜得不对，直接说"改成xxx"就会变成你确认过的正式设定。生成正文时，假设的内容允许写手根据场景需要做适度调整，不像你明确锁定的设定那样是绝对不能违反的硬性要求。

### 规则型字段
类型、基调、篇幅、场景、必含内容、禁止内容——这些是相对固定、不太需要反复讨论的设定项。其中"必含"和"禁止"是硬性要求：必含的内容正文里必须出现，禁止的内容绝不能出现。口语化的说法也算数，比如你说"主角不能死"，会被自动理解成"死亡"要进禁止列表，不需要你说得很正式。

### 冲突提示（黄色/红色的提示框）
系统发现设定之间可能存在矛盾时会主动标出来，比如你既要求"激烈枪战"又要求"零暴力画面"。它不会替你决定怎么取舍，只会把冲突点摊开给你看，你可以选择调整任意一边，或者干脆不管（有时候"矛盾"是你故意设计的张力，不一定是错误）。

### 疑似指令注入提示
如果你的输入里包含类似"忽略以上设定""你现在是新的AI"这种试图操纵系统行为的内容，会被识别并标记出来提醒你注意，但系统仍然会正常处理这段话里其他真实的创作内容，不会因为检测到可疑内容就整段拒绝处理。

## 生成正文时会发生什么

### 长篇会自动分段
如果一幕的场次大纲比较长，系统会自动拆成几段依次生成，不需要你手动操作。段与段之间会自动衔接——后一段会参考前一段的原文（保持文风一致）和一份滚动更新的"事实清单"（保证人物状态、已发生的事情不会前后矛盾）。生成过程中会显示"第几段/共几段"的进度。如果某一段因为篇幅原因被截断了，界面上会提示出来，可以考虑重新生成。

### 双模式
同一份设定可以分别生成"小说"（第三人称叙述、对白融入段落）或"剧本"（场景标题 + 动作描述 + 标准对白格式）两种正文，互不影响，可以分别生成、分别保存多个版本。

### 版本不会互相覆盖
每次生成都会存成新版本（`novel_v1.md`、`novel_v2.md`……），旧版本不会丢，可以随时对照查看、删除不满意的版本。

## 系列 / 多幕续写

如果想写一个连续的多幕故事：

1. 在某个已经"收尾"的项目基础上，新建一个项目并选择"承接自"这个项目
2. 新一幕会自动继承上一幕确立的人物、场景等设定，**但主线（want/obstacle）需要重新聊**——新一幕应该是上一幕结局的合理延续，不是简单复制上一幕的冲突
3. 生成新一幕正文时，会自动参考上一幕的正文（保持文风）和更早几幕的事实清单（保持情节一致），不需要手动整理"前情提要"
4. 系列里所有幕次都生成完之后，可以一键导出成一份完整合集文档（纯拼接，不会重新调用模型）

**几个容易搞混的地方**：
- 续写关系一旦建立就不能在界面上更改，只能删掉这一幕重新创建——建立前系统会让你确认一次
- 如果你选择续写的项目并不是这条故事线目前最新的一幕（比如已经有别的幕续写过它了），系统会提示你，因为这种情况通常是选错了，但也允许你确认后继续（用于故意开一个新分支的情况）
- 上一幕如果后来又被重新生成过一次，这一幕当初参考的版本就过期了，界面上会有提示，建议重新生成这一幕

## 一些使用建议

- 描述故事的时候不需要按"类型、人物、场景"这个顺序说清楚，想到什么说什么，系统会自己整理归类
- 想修改某一项设定，直接点击右侧对应的卡片，输入框会自动帮你填好半句话，接着说完你想改成什么就行，不需要重新描述整个故事
- 说"收尾"之前可以先输入"状态"看一眼当前收集到的全部内容，确认没有遗漏或者理解错的地方再确认收尾——收尾时的描述会成为这一幕结局的正式记录，后续续写会以它为基础
- 生成的正文不满意，可以直接重新生成（会存成新版本，不影响已有版本），也可以先回到对话里调整场次大纲或人物设定再重新生成
